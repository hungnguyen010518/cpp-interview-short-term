# Bài 13 — Tính năng C++11/14/17

!!! abstract "🎯 Học xong bài này, bạn sẽ"

## 📖 Giải thích

### 0. Phiên bản nào có gì

Mỗi vài năm, ủy ban chuẩn C++ phát hành một bản chuẩn, gọi theo năm: C++11, C++14, C++17. Khóa học này biên dịch bằng `g++ -std=c++17`, nên mọi thứ ở bài này đều dùng được. Bảng dưới là bản đồ, mỗi tính năng có mục riêng ở dưới.

| Phiên bản | Tính năng trong bài |
|---|---|
| C++11 | `auto`, `for` duyệt dãy, `nullptr`, lambda, `enum class`, `override`/`final`, `constexpr`, `static_assert`, `std::move` và smart pointer |
| C++14 | `std::make_unique`, lambda có tham số `auto`, `constexpr` thoải mái hơn |

## C++11

### 1. `auto` và cái bẫy làm rơi `const` và `&`

Từ [Bài 09](09-unique-ptr.md) ta đã viết `auto p = std::make_unique<Cay>(5);`: `auto` nghĩa là "trình biên dịch tự đoán kiểu từ vế phải". Nó tiện khi kiểu quá dài, nhưng có một quy tắc phải nhớ: **`auto` bỏ `&` và `const` ở ngoài cùng của kiểu gốc**. Muốn giữ lại thì bạn tự viết ra: `auto&`, `const auto&`.

```cpp
#include <iostream>

int main() {
    int a = 10;
    int& ra = a;                         // (1)
    auto b = ra;                         // (2)
    b = 99;                              // (3)
    std::cout << "a = " << a << ", b = " << b << "\n";
    auto& c = ra;                        // (4)
    c = 7;                               // (5)
    std::cout << "a = " << a << "\n";
    const int k = 5;                     // (6)
    auto m = k;                          // (7)
    m = 6;                               // (8)
    const auto& n = k;                   // (9)
    std::cout << "k = " << k << ", m = " << m << ", n = " << n << "\n";
    return 0;
}
```

| Bước | Dòng | Chuyện gì xảy ra |
|---|---|---|
| 1 | `int a = 10;` | `a` bằng 10 |
| 2 | (1) | `ra` là biệt danh của `a` ([Bài 06](06-tham-chieu-const.md)) |
| 3 | (2) | `auto` bỏ `&`: `b` là `int` mới, **bản sao** giá trị 10 |
| 4 | (3) | Sửa `b` thành 99, `a` không đổi; in `a = 10, b = 99` |
| 5 | (4) | `auto&` giữ `&`: `c` là biệt danh của `a` |
| 6 | (5) | `c = 7` sửa chính `a`; in `a = 7` |
| 7 | (6) | `k` là hằng 5 |
| 8 | (7) | `auto` bỏ `const` ngoài cùng: `m` là `int` thường, bản sao |
| 9 | (8) | Sửa `m` được, `k` vẫn 5 |
| 10 | (9) | `const auto&`: `n` là biệt danh chỉ-đọc của `k`, không sao chép |
| 11 | in | `k = 5, m = 6, n = 5` |

**Kết quả khi chạy** (`g++ -std=c++17 -Wall`):

```text
a = 10, b = 99
a = 7
k = 5, m = 6, n = 5
```

**Thử thay đổi: thêm `n = 6;` sau dòng (9).** Mình đã chạy: g++ báo lỗi biên dịch `assignment of read-only reference 'n'` (rút gọn). `const auto&` vừa không sao chép vừa cấm sửa.

!!! warning "Hay nhầm"
    `auto x = tenBienLon;` **sao chép cả đối tượng**, dù `tenBienLon` có là tham chiếu. Nếu chỉ cần xem, hãy viết `const auto& x = tenBienLon;`.

### 2. `for` duyệt dãy (range-based for)

Để duyệt mảng ta từng viết `for (int i = 0; i < n; i++)` rồi `a[i]`. C++11 cho viết gọn: `for (khai báo : dãy)`, đọc là "với từng phần tử trong dãy". Ở bài này dãy là `std::vector`: một **mảng co giãn** (thêm bớt phần tử được), giống slice của Go. Muốn dùng phải `#include <vector>`; viết `std::vector<int> v = {3, 1, 2};` là tạo vector có ba số. Các kiểu chứa như `vector` thuộc thư viện chuẩn STL, sẽ học ở nhóm sau.

Phần khai báo trước dấu `:` chính là luật `auto` của mục 1.

```cpp
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::vector<int> v = {3, 1, 2};               // (1)
    for (auto x : v) {                            // (2)
        x = x * 10;
    }
    for (int x : v) std::cout << x << " ";
    std::cout << "\n";
    for (auto& x : v) {                           // (3)
        x = x * 10;
    }
    for (int x : v) std::cout << x << " ";
    std::cout << "\n";
    std::vector<std::string> ten = {"An", "Binh"};
    for (const auto& t : ten) {                   // (4)
        std::cout << t << "\n";
    }
    return 0;
}
```

| Bước | Dòng | Chuyện gì xảy ra |
|---|---|---|
| 1 | (1) | `v` giữ 3, 1, 2 |
| 2 | (2) | `auto x` bỏ `&`: mỗi vòng `x` là **bản sao** của một phần tử; `x * 10` chỉ sửa bản sao |
| 3 | in | Dòng in dùng `int x` (cũng là bản sao, chỉ để đọc): `3 1 2`, `v` chưa đổi |
| 4 | (3) | `auto& x` là biệt danh của chính phần tử: nhân 10 ngay trong `v` |
| 5 | in | `30 10 20` |
| 6 | (4) | `const auto& t`: xem từng chuỗi, không sao chép, không sửa; in `An` rồi `Binh` |

**Kết quả khi chạy:**

```text
3 1 2 
30 10 20 
An
Binh
```

Dòng đầu có một khoảng trắng ở cuối, do `" "` sau mỗi số. Quy tắc dùng thường ngày: **chỉ xem** thì `const auto&`; **sửa tại chỗ** thì `auto&`; số nhỏ như `int` thì `auto x` cũng không sao.

**Thử thay đổi: ở (3) đổi `auto&` thành `const auto&`.** Mình đã chạy: lỗi biên dịch `assignment of read-only reference 'x'`. Trình biên dịch chặn việc sửa qua tham chiếu hằng.

### 3. `nullptr`

`nullptr` là con trỏ "chưa trỏ vào đâu", đã học ở [Bài 03](03-con-tro-co-ban.md). Nó có từ C++11, thay `NULL` của C (thực chất chỉ là số 0 nên dễ lẫn với số).

### 4. Lambda: hàm viết ngay tại chỗ

Đôi khi ta cần một hàm nhỏ dùng đúng một lần, ví dụ "so sánh hai số để sắp xếp". Viết hẳn một hàm đặt tên riêng thì rườm. **Lambda** là hàm không tên, viết ngay chỗ cần. Cú pháp:

```text
[danh sách bắt](tham số) { thân hàm }
```

- **Tham số** và **thân** giống hàm thường; kiểu trả về tự đoán từ `return`.
- **Danh sách bắt** (capture) là cái hàm thường không có: nó nói các biến **của nơi viết lambda** mà thân hàm được dùng, và dùng theo cách nào. `[=]` nghĩa là chép (copy) các biến dùng tới, `[&]` là giữ tham chiếu tới chúng. Muốn chọn từng biến thì viết `[x]` (chép `x`) hoặc `[&x]` (tham chiếu `x`). `[]` rỗng là không bắt gì.
- Lambda là một giá trị: cất vào biến `auto` và gọi như hàm.

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    auto cong = [](int a, int b) { return a + b; };       // (1)
    std::cout << cong(2, 3) << "\n";                      // (2)

    int heso = 10;
    auto nhanChep = [=](int x) { return x * heso; };      // (3)
    auto nhanThamChieu = [&](int x) { return x * heso; }; // (4)
    heso = 100;                                           // (5)
    std::cout << nhanChep(2) << " " << nhanThamChieu(2) << "\n";  // (6)

    std::vector<int> v = {3, 1, 2};
    std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });  // (7)
    for (int x : v) std::cout << x << " ";
    std::cout << "\n";
    return 0;
}
```

| Bước | Dòng | Chuyện gì xảy ra |
|---|---|---|
| 1 | (1) | Tạo lambda nhận hai `int` trả tổng, cất vào `cong` (chưa chạy gì) |
| 2 | (2) | Gọi `cong(2, 3)`: in `5` |
| 3 | `int heso = 10;` | `heso` bằng 10 |
| 4 | (3) | `[=]`: tại **lúc tạo**, `nhanChep` chép `heso` (đang là 10) vào trong nó |
| 5 | (4) | `[&]`: `nhanThamChieu` giữ tham chiếu tới chính `heso` |
| 6 | (5) | `heso` đổi thành 100 |
| 7 | (6) | `nhanChep(2)` dùng bản chép 10 nên ra 20; `nhanThamChieu(2)` đọc `heso` hiện tại là 100 nên ra 200 |
| 8 | (7) | `std::sort` (trong `<algorithm>`) sắp xếp dãy từ `v.begin()` (đầu) tới `v.end()` (cuối). Lambda là câu trả lời cho "`a` có đứng trước `b` không": ở đây `a > b`, nên số lớn đứng trước |
| 9 | in | `3 2 1` |

**Kết quả khi chạy:**

```text
5
20 200
3 2 1 
```

Cặp `20 200` là điểm mấu chốt: cùng một thân hàm, khác nhau chỉ ở danh sách bắt.

**Thử thay đổi: trong `nhanChep` thêm `heso = 1;` trước `return`.** Mình đã chạy: lỗi biên dịch `assignment of read-only variable 'heso'`. Lambda `[=]` coi các bản chép là hằng; có từ khóa `mutable` để cho phép sửa, bài này chỉ nêu tên.

!!! info "Bạn biết Go?"
    Lambda giống **closure** của Go: `func(x int) int { return x * heso }` cũng dùng được biến bên ngoài. Khác nhau quan trọng: closure Go bắt biến **theo tham chiếu** và bộ gom rác giữ biến sống chừng nào closure còn dùng nó. C++ cho **bạn chọn** (`[=]` chép, `[&]` tham chiếu), và **không có gì giữ biến sống giùm**.

Chỗ khác đó chính là cái bẫy. Lambda `[&]` chỉ cầm tham chiếu tới biến gốc; nếu lambda bị trả ra khỏi hàm, biến cục bộ đã chết theo hàm (đúng chuyện stack ở [Bài 02](02-stack-heap-static.md)), và lambda cầm một tham chiếu treo ([Bài 06](06-tham-chieu-const.md)). Đoạn dưới là **hành vi không xác định**; mình không chạy nó và không nói nó in gì. (`auto` ở kiểu trả về, từ C++14, nghĩa là để trình biên dịch đoán kiểu từ lệnh `return`.)

```cpp
// bo-qua-kiem-tra
auto taoDem() {
    int n = 5;
    return [&] { return n; };    // lambda giữ tham chiếu tới n, mà n chết khi hàm xong
}
// auto f = taoDem();  f() đọc n đã chết
```

Cách sửa: bắt bản chép, `[=]` hoặc `[n]`, để lambda mang giá trị đi theo mình. Dùng `[&]` chỉ khi lambda được dùng xong trong lúc biến gốc còn sống, như `nhanThamChieu` ở trên.

### 5. `enum class`

`enum` là kiểu liệt kê: một nhóm tên gọi cho vài hằng số. `enum` kiểu cũ có hai tật: các tên **tràn ra ngoài** (viết thẳng `Xanh`, dễ đụng tên) và **tự đổi sang `int`**, nên so sánh nhầm kiểu mà không ai báo. C++11 thêm `enum class` sửa cả hai: phải viết `MauSac::Tim`, và muốn ra số phải tự đổi bằng `static_cast` ([Bài 01](01-bo-nho-byte-dia-chi.md)).

```cpp
#include <iostream>

enum Cu { Do, Xanh };                       // (1)
enum class MauSac { Vang, Tim };            // (2)

int main() {
    int i = Xanh;                           // (3)
    MauSac m = MauSac::Tim;                 // (4)
    int j = static_cast<int>(m);            // (5)
    std::cout << i << " " << j << "\n";
    std::cout << (m == MauSac::Tim) << "\n";
    return 0;
}
```

| Bước | Dòng | Chuyện gì xảy ra |
|---|---|---|
| 1 | (1), (2) | `Cu` kiểu cũ có `Do` = 0, `Xanh` = 1; `MauSac` có `Vang` = 0, `Tim` = 1 |
| 2 | (3) | `Xanh` dùng thẳng không cần tiền tố, tự đổi sang `int`: `i` = 1 |
| 3 | (4) | Với `enum class` phải viết `MauSac::Tim` |
| 4 | (5) | Ra số thì tự đổi bằng `static_cast`: `j` = 1 |
| 5 | in | `1 1`, rồi `m == MauSac::Tim` đúng nên in `1` |

**Kết quả khi chạy:**

```text
1 1
1
```

**Thử thay đổi: viết `int i = MauSac::Tim;` ở (3).** Mình đã chạy: lỗi `cannot convert 'MauSac' to 'int' in initialization`. In thẳng `std::cout << m` cũng là lỗi biên dịch (`no match for 'operator<<'`): phải `static_cast` trước.

### 6. `override` và `final`

Hai từ khóa này đi cùng **kế thừa** và hàm `virtual`, thứ nhóm OOP sẽ dạy; bài này chưa dạy nên không có ví dụ. Chỉ cần biết hai điều. `override` đánh dấu "hàm này ghi đè hàm của lớp cha" để trình biên dịch **báo lỗi** nếu bạn viết sai chữ ký. `final` cấm ghi đè tiếp, hoặc cấm kế thừa tiếp một lớp. Cả hai có từ C++11 và sẽ quan trọng khi ta học kế thừa.

### 7. `constexpr` và `static_assert`

Có những giá trị trình biên dịch tính được ngay khi **biên dịch**, như `5 * 5`. Tính trước thì chương trình chạy không tốn công, và cho phép dùng giá trị đó ở chỗ đòi hằng (như cỡ mảng). `constexpr` là cách bạn nói với trình biên dịch "việc này được phép tính lúc biên dịch":

- **Biến `constexpr`**: bắt buộc phải tính được lúc biên dịch, và ngầm là `const`.
- **Hàm `constexpr`**: *có thể* chạy lúc biên dịch khi đối số đều là giá trị cố định; gọi với giá trị chỉ biết lúc chạy thì nó vẫn chạy **lúc chạy** như hàm thường.
- `static_assert(điều kiện, "lời nhắn")` kiểm tra điều kiện lúc biên dịch: sai thì **không biên dịch được**.

```cpp
#include <iostream>

constexpr int binhPhuong(int x) { return x * x; }     // (1)

int main() {
    constexpr int a = binhPhuong(5);                  // (2)
    static_assert(a == 25, "a phai bang 25");         // (3)
    int n = 6;                                        // (4)
    int b = binhPhuong(n);                            // (5)
    std::cout << a << " " << b << "\n";
    return 0;
}
```

| Bước | Dòng | Chuyện gì xảy ra |
|---|---|---|
| 1 | (2) | `5` là hằng, biến `a` đòi tính lúc biên dịch: trình biên dịch tự tính `binhPhuong(5)` (định nghĩa ở (1)) = 25 |
| 2 | (3) | `static_assert` kiểm tra `a == 25` ngay lúc biên dịch: đúng nên qua |
| 3 | (4) | `n` là biến thường, giá trị chỉ biết khi chạy |
| 4 | (5) | `binhPhuong(n)` với `n` thường: hàm chạy lúc chạy, `b` = 36 |
| 5 | in | `25 36` |

**Kết quả khi chạy:**

```text
25 36
```

Hai **Thử thay đổi** (mình đã chạy cả hai). Một: đổi `static_assert(a == 25` thành `a == 26` thì g++ báo `static assertion failed: a phai bang 25` và không tạo ra chương trình. Hai: đổi dòng (5) thành `constexpr int b = binhPhuong(n);` thì g++ báo `the value of 'n' is not usable in a constant expression`: biến `constexpr` đòi tính lúc biên dịch mà `n` chưa biết.

!!! warning "Hay nhầm"
    `const` chỉ nói "không được sửa sau khi gán", còn giá trị có thể chỉ biết lúc chạy (`const int c = n;` là hợp lệ). `constexpr` mới là lời yêu cầu "tính lúc biên dịch". Với hàm `constexpr` gọi bằng giá trị thường, chuẩn **không** hứa nó chạy lúc biên dịch: chỗ nào *đòi* hằng (biến `constexpr`, `static_assert`) mới ép nó.

### 8. `std::move` và smart pointer

C++11 cũng là bản đưa vào `std::move`, tham chiếu rvalue, `unique_ptr`, `shared_ptr`. Những thứ này bạn đã học ở [Bài 09](09-unique-ptr.md), [Bài 10](10-shared-ptr-weak-ptr.md) và [Bài 12](12-move-semantics.md), không nhắc lại.

## C++14

### 9. `make_unique`, lambda tham số `auto`, `constexpr` thoải mái hơn

`std::make_unique` đã dạy ở [Bài 09](09-unique-ptr.md): nó có từ C++14 (C++11 chỉ có `make_shared`, chưa có `make_unique`).

**Lambda tham số `auto`** (generic lambda): viết `auto` ở chỗ kiểu tham số thì lambda dùng được với nhiều kiểu, trình biên dịch tạo bản riêng cho mỗi kiểu bạn gọi.

**`constexpr` thoải mái hơn**: ở C++11, thân hàm `constexpr` chỉ được là một lệnh `return`. C++14 cho phép biến cục bộ và vòng lặp.

```cpp
#include <iostream>
#include <string>

constexpr int tong(int n) {                           // (1)
    int s = 0;
    for (int i = 1; i <= n; i++) s += i;
    return s;
}

int main() {
    auto in = [](auto x) { std::cout << x << "\n"; }; // (2)
    in(42);                                           // (3)
    in(2.5);                                          // (4)
    in(std::string("xin chao"));                      // (5)
    static_assert(tong(4) == 10, "sai");              // (6)
    std::cout << tong(4) << "\n";
    return 0;
}
```

| Bước | Dòng | Chuyện gì xảy ra |
|---|---|---|
| 1 | (2) | Tạo lambda có tham số `auto x`, cất vào `in` |
| 2 | (3) | `in(42)`: bản cho `int`, in `42` |
| 3 | (4) | `in(2.5)`: bản cho `double`, in `2.5` |
| 4 | (5) | `in(std::string(...))`: bản cho chuỗi, in `xin chao` |
| 5 | (6) | `tong(4)` (hàm (1), có vòng `for`) tính lúc biên dịch = 10; `static_assert` qua |
| 6 | in | Gọi `tong(4)` lần nữa, in `10` |

**Kết quả khi chạy:**

```text
42
2.5
xin chao
10
```

**Thử thay đổi: biên dịch bằng `-std=c++11`.** Mình đã chạy: g++ báo hai lỗi chính, `body of 'constexpr' function 'tong' not a return-statement` và `use of 'auto' in lambda parameter declaration only available with '-std=c++14'` (rút gọn). Đó là cách kiểm tra "tính năng này của bản nào".

!!! info "Bạn biết Go?"
    `auto` ở tham số lambda cho cảm giác giống **generics** của Go (`func in[T any](x T)`), với một khác biệt: ở C++ trình biên dịch dựng một bản riêng cho mỗi kiểu gọi, như bảng đã vẽ. Chỉ là so sánh gần đúng, đủ để hình dung.

## C++17

### 10. Structured binding: tách một bộ thành nhiều biến

Hàm chỉ trả được một giá trị, nên muốn trả hai thì gói vào một `std::pair` (cặp hai giá trị, trong `<utility>`) hoặc một struct. Từ C++17, `auto [a, b] = giaTri;` tách cặp (hoặc struct) ra thành hai biến có tên, hơi giống Go gán nhiều giá trị `q, r := chia(17, 5)`. Luật `auto` của mục 1 vẫn đúng: `auto [a, b]` **chép**, còn `auto& [a, b]` là biệt danh của các trường gốc.

### 11. `std::optional`: chiếc hộp có thể rỗng

Hàm tìm kiếm có thể không tìm thấy. Trước đây người ta trả số ma thuật như `-1` hay con trỏ `nullptr`, rất dễ quên kiểm tra. `std::optional<T>` (trong `<optional>`) là một hộp **hoặc chứa một `T`, hoặc rỗng**. Rỗng viết là `std::nullopt`; kiểm tra bằng cách dùng nó như điều kiện `if (r)`; lấy giá trị bằng `*r`, hoặc `r.value_or(mặc_định)` để có giá trị thay thế khi rỗng.

### 12. `if` có khởi tạo

`if (khởi tạo; điều kiện)`: câu lệnh ở phần đầu chạy trước, rồi mới kiểm tra điều kiện, và biến khai báo ở đó **chỉ sống trong `if`/`else` này**. Nó giúp biến tạm không tràn ra phạm vi bên ngoài.

!!! info "Bạn biết Go?"
    Đây đúng là `if v, ok := m[k]; ok { ... }` của Go: khai báo ở đầu `if`, dùng trong `if`/`else`, hết `if` là biến mất. Chỉ khác cú pháp: C++ viết `if (auto r = tim(...); r) { ... }`. Và `optional` đóng vai cặp `(giá trị, ok)` của Go, gói cả hai vào một giá trị.

```cpp
#include <iostream>
#include <optional>
#include <string>
#include <utility>

std::pair<int, int> chia(int a, int b) {              // (1)
    return {a / b, a % b};
}

struct Diem {
    std::string ten;
    int so;
};

std::optional<int> timDiem(const std::string& ten) {  // (2)
    if (ten == "An") return 9;
    return std::nullopt;                              // (3)
}

int main() {
    auto [thuong, du] = chia(17, 5);                  // (4)
    std::cout << thuong << " " << du << "\n";

    Diem d{"Binh", 7};                                // (5)
    auto& [ten, so] = d;                              // (6)
    so = 8;
    std::cout << ten << " " << d.so << "\n";

    if (auto r = timDiem("An"); r) {                  // (7)
        std::cout << "co: " << *r << "\n";
    } else {
        std::cout << "khong co\n";
    }
    if (auto r = timDiem("Cuong"); r) {
        std::cout << "co: " << *r << "\n";
    } else {
        std::cout << "khong co, mac dinh " << r.value_or(0) << "\n";   // (8)
    }
    return 0;
}
```

| Bước | Dòng | Chuyện gì xảy ra |
|---|---|---|
| 1 | (4) → (1) | `chia(17, 5)` trả cặp `{3, 2}` (thương và dư); `auto [thuong, du]` tách: `thuong` = 3, `du` = 2; in `3 2` |
| 2 | (5) | `Diem d{"Binh", 7};` điền các trường theo thứ tự khai báo: `ten` = "Binh", `so` = 7 |
| 3 | (6) | `auto&` tách `d` thành hai biệt danh: `ten` là `d.ten`, `so` là `d.so` |
| 4 | `so = 8;` | Sửa `so` là sửa thẳng `d.so` |
| 5 | in | `Binh 8` |
| 6 | (7) | `r` là `optional` của `timDiem("An")` → (2): `"An"` khớp, trả 9, hộp chứa 9; `r` đúng nên in `co: 9` |
| 7 | (7) lần hai | `timDiem("Cuong")` → (3): trả `std::nullopt`, hộp rỗng; `r` sai nên vào `else` |
| 8 | (8) | `r.value_or(0)` cho 0 vì hộp rỗng; in `khong co, mac dinh 0` |

**Kết quả khi chạy:**

```text
3 2
Binh 8
co: 9
khong co, mac dinh 0
```

**Thử thay đổi 1: đổi (6) thành `auto [ten, so] = d;` (không `&`).** Mình đã chạy: dòng in thứ hai thành `Binh 7`, vì `so = 8` sửa bản chép chứ không sửa `d`.

**Thử thay đổi 2: dùng `r` sau cả khối `if`/`else`.** Mình đã chạy (thêm `r.value_or(1)` ngay sau `else` thứ hai): lỗi `'r' was not declared in this scope`. Biến của `if` có khởi tạo hết sống cùng `if`.

!!! warning "Hay nhầm"
    `*r` trên hộp **rỗng** là hành vi không xác định, giống giải tham chiếu `nullptr`. Phải kiểm tra `if (r)` trước, hoặc dùng `value_or`. (Mình không chạy trường hợp này.)

### 13. `std::variant`: một trong nhiều kiểu

`std::variant<int, std::string>` (trong `<variant>`) là một giá trị mà **tại mỗi thời điểm chứa đúng một** trong các kiểu đã liệt kê. `std::holds_alternative<int>(v)` hỏi "bây giờ nó đang chứa `int` không", `std::get<int>(v)` lấy giá trị ra. Nếu `get` sai kiểu, nó ném ngoại lệ `std::bad_variant_access` (cú pháp `try`/`catch` ở [Bài 08](08-raii.md)). `std::visit` là cách xử lý gọn hơn, ở đây chỉ nêu tên.

```cpp
#include <iostream>
#include <string>
#include <variant>

int main() {
    std::variant<int, std::string> v = 42;                       // (1)
    std::cout << std::holds_alternative<int>(v) << " " << std::get<int>(v) << "\n";   // (2)
    v = std::string("xin chao");                                 // (3)
    std::cout << std::holds_alternative<int>(v) << " " << std::get<std::string>(v) << "\n";
    try {
        std::cout << std::get<int>(v) << "\n";                   // (4)
    } catch (const std::bad_variant_access&) {
        std::cout << "v khong giu int\n";
    }
    return 0;
}
```

| Bước | Dòng | Chuyện gì xảy ra |
|---|---|---|
| 1 | (1) | `v` đang giữ `int` 42 |
| 2 | (2) | Hỏi "đang giữ `int`?": đúng nên in `1`, rồi `get<int>` lấy 42; in `1 42` |
| 3 | (3) | Gán chuỗi: `v` bỏ `int`, giờ giữ `std::string` |
| 4 | in | `holds_alternative<int>` sai nên in `0`, rồi `get<std::string>` lấy chuỗi; in `0 xin chao` |
| 5 | (4) | `get<int>(v)` khi `v` đang giữ chuỗi: ném `std::bad_variant_access` |
| 6 | `catch` | Bắt được, in `v khong giu int` |

**Kết quả khi chạy:**

```text
1 42
0 xin chao
v khong giu int
```

!!! info "Bạn biết Go?"
    `variant` hơi giống `interface{}` của Go ở chỗ "một biến, nhiều kiểu có thể", nhưng chặt hơn: bạn phải **liệt kê trước** các kiểu cho phép, nên trình biên dịch biết hết các khả năng. Chỉ là so sánh gần đúng.

### 14. `std::string_view`: cửa sổ không sở hữu

Truyền chuỗi vào hàm bằng `std::string` thì sao chép cả chuỗi, bằng `const std::string&` thì bắt người gọi phải có sẵn một `std::string`. `std::string_view` (trong `<string_view>`) là **cửa sổ** nhìn vào các ký tự đã có ở đâu đó: nó chỉ giữ địa chỉ đầu và độ dài, **không sở hữu, không sao chép**. Nó nhận được cả `std::string` lẫn chuỗi hằng như `"hello"`.

```cpp
#include <iostream>
#include <string>
#include <string_view>

void in(std::string_view s) {                         // (1)
    std::cout << s.size() << ": " << s << "\n";
}

int main() {
    std::string ten = "Nguyen Van An";
    in(ten);                                          // (2)
    in("hello");                                      // (3)
    std::string_view sv = ten;                        // (4)
    std::cout << (sv.data() == ten.data()) << "\n";   // (5)
    std::string_view ho = sv.substr(0, 6);            // (6)
    std::cout << ho << "\n";
    return 0;
}
```

| Bước | Dòng | Chuyện gì xảy ra |
|---|---|---|
| 1 | (2) | `in(ten)`: `s` ở (1) là cửa sổ nhìn vào các ký tự của `ten` (không chép); in độ dài và chuỗi: `13: Nguyen Van An` |
| 2 | (3) | `in("hello")`: nhìn thẳng vào chuỗi hằng, không tạo `std::string`; in `5: hello` |
| 3 | (4) | `sv` cũng nhìn vào `ten` |
| 4 | (5) | `.data()` là địa chỉ ký tự đầu mà cửa sổ nhìn; hai địa chỉ giống nhau nên in `1`: không có bản chép nào |
| 5 | (6) | `substr(0, 6)` cắt cửa sổ 6 ký tự đầu, vẫn là cửa sổ, không chép; in `Nguyen` |

**Kết quả khi chạy:**

```text
13: Nguyen Van An
5: hello
1
Nguyen
```

Cái giá là cái bẫy: cửa sổ **không giữ chuỗi sống**. Nếu chuỗi gốc chết trước cửa sổ thì cửa sổ nhìn vào chỗ đã dọn, giống con trỏ treo ([Bài 07](07-new-delete.md)). Hai chỗ rất dễ dính là trả `string_view` nhìn vào biến cục bộ, và gán `string_view` từ một chuỗi **tạm** (chết ngay cuối câu lệnh). Hai đoạn dưới là hành vi không xác định, mình không chạy và không nói chúng in gì.

```cpp
// bo-qua-kiem-tra
#include <string>
#include <string_view>

std::string layTen() { return "Nguyen Van An"; }

std::string_view treo1() {
    std::string s = "xin chao";
    return s;                          // s chết khi hàm xong, cửa sổ nhìn vào s
}

void treo2() {
    std::string_view sv = layTen();    // chuỗi tạm chết cuối dòng này
    // dùng sv ở các dòng sau là đọc chuỗi đã chết
}
```

Quy tắc: `string_view` hợp làm **tham số hàm** (người gọi giữ chuỗi sống suốt lúc gọi), không hợp để cất lâu dài hay trả về từ hàm.

### Ví dụ: bảng điểm nhỏ ghép các mảnh lại

Chương trình dưới dùng vài thứ vừa học: `const auto&`, lambda có bắt, `optional`, `string_view`, `if` có khởi tạo và structured binding. Nó in ai đậu, rồi tìm theo tên.

```cpp
#include <iostream>
#include <optional>
#include <string>
#include <string_view>
#include <vector>

struct HocSinh {
    std::string ten;
    int diem;
};

std::optional<HocSinh> timTheoTen(const std::vector<HocSinh>& ds, std::string_view ten) {
    for (const auto& hs : ds) {                          // (1)
        if (hs.ten == ten) return hs;                    // (2)
    }
    return std::nullopt;                                 // (3)
}

int main() {
    std::vector<HocSinh> ds = {{"An", 9}, {"Binh", 7}, {"Chi", 8}};
    int nguong = 8;
    auto dau = [nguong](const HocSinh& hs) { return hs.diem >= nguong; };   // (4)
    for (const auto& hs : ds) {
        std::cout << hs.ten << (dau(hs) ? " dau" : " truot") << "\n";       // (5)
    }
    if (auto kq = timTheoTen(ds, "Binh"); kq) {          // (6)
        auto [ten, diem] = *kq;                          // (7)
        std::cout << "tim thay " << ten << " " << diem << "\n";
    }
    if (auto kq = timTheoTen(ds, "Dung"); !kq) {         // (8)
        std::cout << "khong co Dung\n";
    }
    return 0;
}
```

| Bước | Dòng | Chuyện gì xảy ra |
|---|---|---|
| 1 | `ds`, `nguong` | `ds` giữ ba học sinh (`{"An", 9}` điền `ten` rồi `diem`); `nguong` = 8 |
| 2 | (4) | Lambda bắt `nguong` bằng `[nguong]` (chép 8); nhận một `HocSinh`, trả "điểm có từ 8 trở lên không" |
| 3 | (5) | Duyệt bằng `const auto&` (không chép học sinh); An 9 đậu, Binh 7 trượt, Chi 8 đậu: in ba dòng đầu |
| 4 | (6) | Gọi `timTheoTen(ds, "Binh")`: `"Binh"` chuyển thành `string_view` không chép |
| 5 | (1), (2) | Duyệt `ds`; tới Binh thì `hs.ten == ten`, trả `hs` (hộp chứa bản chép của Binh) |
| 6 | (6) | `kq` có giá trị nên vào khối `if` |
| 7 | (7) | `auto [ten, diem] = *kq;` tách học sinh thành hai biến; in `tim thay Binh 7` |
| 8 | (8), (1) | Tìm "Dung": duyệt hết không khớp |
| 9 | (3) | Trả `std::nullopt`, `kq` rỗng, `!kq` đúng; in `khong co Dung` |

**Kết quả khi chạy:**

```text
An dau
Binh truot
Chi dau
tim thay Binh 7
khong co Dung
```

Mình đã chạy tất cả các chương trình của bài này với `-fsanitize=address,undefined`: không báo gì, thoát mã 0.

## 🎤 Câu hỏi phỏng vấn hay gặp

??? question "Những bẫy khi dùng `auto`?"
    `auto` bỏ `&` và `const` ở ngoài cùng của kiểu gốc, nên `auto x = ref;` âm thầm sao chép. Muốn tham chiếu thì viết `auto&`, muốn chỉ đọc không chép thì `const auto&`; trong `for (const auto& x : v)` cũng vậy. Mình đã chạy thử: sửa `x` trong `for (auto x : v)` không đổi `v`.

??? question "Lambda bắt `[=]` khác `[&]` thế nào? Rủi ro?"
    `[=]` chép các biến lambda dùng tới tại lúc **tạo** lambda; `[&]` giữ tham chiếu tới biến gốc, nên thấy được các thay đổi về sau. Rủi ro: lambda `[&]` mà sống lâu hơn biến (ví dụ trả khỏi hàm) thì giữ tham chiếu treo, là hành vi không xác định. Khác closure của Go, C++ không giữ biến sống giùm.

??? question "`constexpr` khác `const` thế nào?"
    `const` chỉ cấm sửa sau khi gán; giá trị có thể chỉ biết lúc chạy. Biến `constexpr` bắt buộc tính được lúc biên dịch và ngầm là `const`. Hàm `constexpr` có thể chạy lúc biên dịch nếu đối số là hằng; gọi với giá trị lúc chạy thì chạy lúc chạy như hàm thường.

??? question "`enum class` hơn `enum` thường ở đâu?"
    Có phạm vi riêng (`MauSac::Tim`, tên không tràn ra ngoài) và không tự đổi sang `int`: muốn ra số phải `static_cast`. Nhờ đó ít đụng tên và ít so sánh nhầm kiểu mà trình biên dịch không báo.

??? question "`override` và `final` để làm gì?"
    `override` đánh dấu hàm ghi đè hàm ảo của lớp cha, để trình biên dịch báo lỗi nếu chữ ký không khớp. `final` cấm ghi đè hàm ảo, hoặc cấm kế thừa tiếp một lớp. Cả hai có từ C++11; ví dụ cụ thể thuộc nhóm OOP.

??? question "Kể vài tính năng C++17 bạn hay dùng."
    `std::optional` (kết quả có thể không có), `std::variant` (một trong vài kiểu), `std::string_view` (cửa sổ không sở hữu), structured binding, `if` có khởi tạo, `std::filesystem`. Nhớ nói thêm rủi ro: `string_view` treo khi chuỗi gốc chết trước nó. Lambda và `auto` là của C++11, lambda tham số `auto` và `make_unique` của C++14.

## ⚠️ Lỗi thường gặp

!!! warning "Lỗi 1: Lambda `[&]` trả ra khỏi hàm"
    Biến cục bộ chết khi hàm xong mà lambda vẫn cầm tham chiếu tới nó: hành vi không xác định (đoạn code ở mục 4). Hãy bắt bản chép bằng `[=]` hoặc `[n]`.

!!! warning "Lỗi 2: `auto x = tenBienLon;` hoặc `for (auto x : v)` sao chép ngầm"
    `auto` bỏ `&`, nên mỗi lần là một bản chép đầy đủ (và sửa `x` không đổi gốc). Chỉ xem thì `const auto&`, sửa tại chỗ thì `auto&`.

!!! warning "Lỗi 3: `std::string_view` nhìn vào chuỗi đã chết"
    Trả `string_view` của biến cục bộ, hoặc gán nó từ chuỗi tạm, là để cửa sổ nhìn vào chỗ đã dọn (mục 14, hành vi không xác định). Chỉ dùng nó khi chuỗi gốc chắc chắn còn sống lâu hơn.

- `1`, vì `x` chỉ là bản sao của phần tử
- Lỗi biên dịch, vì `x` không được phép sửa

<p class="giai-thich" markdown>`auto x` bỏ `&` nên mỗi vòng `x` là một bản sao của phần tử; gán 0 cho bản sao không đụng tới `v`, vì vậy `v[0]` vẫn là 1 (mình đã chạy). Muốn sửa thật phải viết `auto& x`. Vòng lặp không đổi thứ tự hay giá trị phần tử nào, và `x` sửa được vì không có `const`, nên không có lỗi biên dịch.</p>
</div>

<div class="cau-hoi" data-dap-an="1" markdown>
**Câu 2.** Đọc đoạn code sau. Dòng cuối in ra gì?

```text
int n = 1;
auto f = [=] { return n; };
n = 5;
std::cout << f();
```

- `1`, vì lambda đã chép `n` ngay khi được tạo
- `5`, vì lambda luôn đọc giá trị mới nhất của `n`
- `6`, vì lambda cộng thêm lần đổi của `n`
- `0`, vì lambda chưa được gán giá trị cho `n`

<p class="giai-thich" markdown>`[=]` chép `n` (lúc đó bằng 1) vào lambda ngay khi nó được tạo, nên đổi `n` về sau không ảnh hưởng và `f()` trả 1 (mình đã chạy). Với `[&]` thì mới ra 5, vì khi đó lambda đọc chính `n`. Không có phép cộng nào giữa giá trị cũ và mới, và lambda không có giá trị 0 nào cả vì `n` đã có 1 từ trước.</p>
</div>

<div class="cau-hoi" data-dap-an="2" markdown>
**Câu 3.** Đọc đoạn code sau. g++ xử lý dòng thứ hai thế nào?

```text
int n = 4;
constexpr int a = n * 2;
```

- Biên dịch được, vì `n * 2` luôn tính được
- Lỗi biên dịch, vì `n` chưa biết khi biên dịch
- Biên dịch được nhưng `a` chỉ có giá trị lúc chạy
- Lỗi lúc chạy, vì `a` không sửa được

<p class="giai-thich" markdown>Biến `constexpr` bắt buộc tính được lúc biên dịch, mà `n` là biến thường nên giá trị chỉ biết lúc chạy: g++ báo `the value of 'n' is not usable in a constant expression` (mình đã chạy). Không có chế độ "`constexpr` mà tính lúc chạy" cho biến. Và lỗi này xảy ra ở bước biên dịch, không đợi tới lúc chạy.</p>
</div>

<div class="cau-hoi" data-dap-an="4" markdown>
**Câu 4.** Đọc đoạn code sau. g++ xử lý dòng cuối thế nào?

```text
enum class Mau { Do, Xanh };
Mau m = Mau::Xanh;
int i = m;
```

- Biên dịch được, `i` bằng 1 vì `Xanh` là giá trị thứ hai
- Biên dịch được, `i` bằng 0 vì `enum class` bắt đầu từ 0
- Lỗi lúc chạy, vì `m` không phải `int`
- Lỗi biên dịch, vì `enum class` không đổi sang `int`

<p class="giai-thich" markdown>`enum class` không tự đổi sang `int`: g++ báo `cannot convert 'Mau' to 'int' in initialization` (mình đã chạy). Muốn lấy số phải viết `static_cast<int>(m)`, khi đó mới ra 1. Với `enum` kiểu cũ thì dòng này biên dịch được, đó là điểm khác nhau chính. Lỗi này nằm ở bước biên dịch, nên không có chuyện chạy rồi mới báo.</p>
</div>

<div class="cau-hoi" data-dap-an="2" markdown>
**Câu 5.** Đọc đoạn code sau. Sau ba dòng này, cửa sổ nào chắc chắn đang nhìn vào chuỗi đã bị hủy?

```text
std::string s = "xin chao";
std::string_view a = s;
std::string_view b = std::string("tam");
```

- Cả `a` lẫn `b`, vì `string_view` không giữ chuỗi
- Chỉ `b`, vì chuỗi tạm bị hủy ngay cuối dòng lệnh
- Chỉ `a`, vì `s` là biến cục bộ nên đã chết
- Không cửa sổ nào, vì `string_view` tự sao chép

<p class="giai-thich" markdown>`b` nhìn vào một chuỗi tạm, bị hủy ngay khi câu lệnh kết thúc, nên `b` nhìn vào chỗ đã dọn. `a` nhìn vào `s`, mà `s` còn sống đến hết phạm vi nên `a` vẫn dùng được. `string_view` không sao chép gì cả, nên ý "không cửa sổ nào treo vì nó tự sao chép" là sai (mình không chạy đoạn này vì dùng `b` là hành vi không xác định).</p>
</div>

<div class="cau-hoi" data-dap-an="3" markdown>
**Câu 6.** Hàm tìm một số trong danh sách, có thể không tìm thấy. Kiểu trả về nào hợp nhất theo C++17?

- `std::string_view`, vì cửa sổ có thể rỗng
- `std::variant<int, bool>`, vì `bool` báo có hay không
- `std::optional<int>`, vì hộp có thể rỗng
- `std::nullopt`, vì nó nghĩa là rỗng

<p class="giai-thich" markdown>`std::optional<int>` là kiểu dành cho "có thể có hoặc không có một `int`", thay cho số ma thuật như `-1`. `std::nullopt` chỉ là **giá trị** rỗng để trả về, không phải một kiểu. `string_view` là cửa sổ nhìn chuỗi chứ không chứa số. `variant<int, bool>` chứa được cả hai kiểu nhưng ép người dùng tự ghép nghĩa, và không diễn tả đúng ý "không có".</p>
</div>

<div class="cau-hoi" data-dap-an="4" markdown>
**Câu 7.** Một hàm tạo lambda `[&]` dùng biến cục bộ của hàm rồi trả lambda ra ngoài. Chuyện gì xảy ra khi gọi lambda đó?

- An toàn, vì C++ giữ biến sống giống Go
- An toàn, vì `[&]` tự chép biến khi hàm kết thúc
- Lỗi biên dịch, vì lambda không được trả về
- Hành vi không xác định, vì tham chiếu đã treo

<p class="giai-thich" markdown>Biến cục bộ chết khi hàm xong, còn `[&]` chỉ giữ tham chiếu tới biến gốc nên thành tham chiếu treo; dùng nó là hành vi không xác định. Closure của Go thì khác: bộ gom rác giữ biến sống, còn C++ không có cơ chế đó. `[&]` không tự chép gì (đó là việc của `[=]`), và lambda trả ra khỏi hàm là hợp lệ, trình biên dịch không chặn.</p>
</div>

<div class="cau-hoi" data-dap-an="1" markdown>
**Câu 8.** Hàm `constexpr int f(int x)` được gọi bằng `f(n)`, trong đó `n` là giá trị chỉ biết khi chương trình chạy (ví dụ người dùng nhập). Điều gì xảy ra?

- Hàm chạy lúc chạy, vì giá trị `n` chưa biết trước
- Lỗi biên dịch, vì `n` chưa biết lúc biên dịch
- Hàm chạy lúc biên dịch, vì đã khai báo `constexpr`
- Chương trình dừng, vì hàm `constexpr` cấm gọi lúc chạy

<p class="giai-thich" markdown>Hàm `constexpr` chỉ **có thể** chạy lúc biên dịch khi đối số là hằng; với `n` lúc chạy thì nó chạy lúc chạy như hàm thường (mình đã chạy, nhập 21 ra 42). Lỗi biên dịch chỉ xuất hiện khi cố ép kết quả vào chỗ đòi hằng, như `constexpr int y = f(n);`. Chữ `constexpr` không bắt hàm chạy lúc biên dịch, và không có luật cấm gọi hàm `constexpr` lúc chạy.</p>
</div>

## 🔑 Tóm tắt

1. **C++11**: `auto`, `for` duyệt dãy, `nullptr`, lambda, `enum class`, `override`/`final`, `constexpr`, `static_assert`, smart pointer, `std::move`. **C++14**: `make_unique`, lambda tham số `auto`, `constexpr` có biến và vòng lặp. **C++17**: structured binding, `optional`, `variant`, `string_view`, `if` có khởi tạo, `filesystem`.
2. `auto` bỏ `&` và `const` ngoài cùng: chỉ xem thì `const auto&`, sửa tại chỗ thì `auto&`; `for (auto x : v)` sao chép từng phần tử.
3. Lambda là `[bắt](tham số){thân}`: `[=]` chép lúc tạo, `[&]` giữ tham chiếu và treo nếu lambda sống lâu hơn biến; khác closure của Go, C++ không giữ biến sống giùm.
4. `constexpr` cho phép tính lúc biên dịch (biến thì bắt buộc, ngầm `const`; hàm gọi với giá trị lúc chạy vẫn chạy lúc chạy); `const` chỉ là không cho sửa. `enum class` có phạm vi riêng và không tự đổi sang `int`.
5. `optional` là hộp có thể rỗng, `variant` giữ một trong vài kiểu (`holds_alternative`, `get`), `string_view` là cửa sổ không sở hữu nên treo khi chuỗi gốc chết trước, và `if (khởi tạo; điều kiện)` giới hạn biến trong câu `if`.
